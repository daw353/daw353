# H1/H2 사전등록 부속 감사

`audit_v1.py` — 트리거 발화 빈도와 거래 비용 하한만 측정하는 감사 스크립트.
**트리거 이후의 미래 수익률은 계산하지 않는다** (확증 예산 미소모).

## 모드

| 명령 | 측정 대상 |
|---|---|
| `python audit_v1.py --mode freq --days 180` | 트리거 A/B 발화 빈도, 일별 분포, 무신호 최장 구간, 월별 F5 체크, 동시발화 군집 |
| `python audit_v1.py --mode cost --rounds 20 --interval 60` | 유니버스 전 종목 실시간 스프레드 → 왕복비용 하한 |
| `python audit_v1.py --source synthetic --days 180` | 파이프라인 자가점검(합성 데이터). **증거 아님. 판정 사용 금지.** |

산출물은 `audit_out/`에 저장 (`events_*.csv`, `summary_*.json`, `cost_matrix.csv`).

## 트리거 정의 (CONFIG 동결, 실행 중 재량 조정 금지)

- **A_proxy** = `15m 수익률 < -1.5σ(직전 7일)` AND `15m quote 거래대금 > 직전 30일 P99`
- **B** = `거래대금 z(직전 30일) > 3` AND `15m 수익률 > 0`
- 종목별·트리거별 쿨다운 4시간, 유니버스 = 30일 중위 일거래대금 순위 20~150위 USDT 무기한선물

임계값(P99, 평균/표준편차)은 **직전** 30일 분포로 하루 1회 갱신하고, σ는 **직전** 7일 수익률로
매 봉 갱신한다. 워밍업 30일 이후의 봉만 판정 대상이다 — 미래 정보 미사용.

## 데이터 현실 고지

과거 청산(강제 체결) 내역은 무료 REST로 제공되지 않는다(바이낸스 `allForceOrders` 폐지).
따라서 감사 구간의 트리거 A는 위의 **프록시**다. 프록시-실제 청산 대응률은 라이브 단계에서
`forceOrder` 웹소켓 로깅으로 별도 검증한다.

## 결과 해석 시 주의

- `F5_check(A_month<10)`: **완전월만** 판정한다. 관측 구간에 절단된 달은
  `F5_partial_months_excluded`에 분리 기록되며 F5 판정에 쓰지 않는다(절단 때문에 건수가 낮게 나옴).
- `roundtrip_lower_bound`는 **하한**이다 = 수수료 2회 + 중위 스프레드. 슬리피지 미포함.
  `--fee`는 가정값이므로 본인 계정 실제 수수료로 교체해야 한다.
- 시간대별 비용 매트릭스는 서로 다른 시간대(한국 새벽/저녁, 미국 개장)에 `--mode cost`를
  반복 실행해 모아야 한다. CSV의 `hours_utc` 열에 샘플이 수집된 UTC 시(hour)가 기록된다.

## 실행 환경

`pip install requests` 만 필요(그 외 표준 라이브러리).

바이낸스는 일부 지역 IP를 차단한다(HTTP 451). 차단된 위치에서는 스크립트가 즉시 명확한
메시지와 함께 종료된다 — 구글 Colab의 미국 리전 IP도 흔히 차단되므로, 차단되지 않은
위치에서 실행하거나 `BASE_FAPI`를 접근 가능한 리전 엔드포인트로 교체할 것.
